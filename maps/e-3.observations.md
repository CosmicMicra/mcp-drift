# e-3 — observations (read after labelling)

1. **Env-secret read already existed; it only moved and was renamed**
   - Evidence: old servicenow_api_mcp.py:33-38 `environment_password = os.environ.get("PASSWORD", None)` etc.; new inline `default=os.environ.get("SERVICENOW_PASSWORD", None)`.
   - Why it matters: the scanner sees `os.environ` inside the tool definition for the first time, but the tool used the same secrets before through module globals.
   - Confidence: high.

2. **The old generic env names collided with common OS variables (fixed by this change)**
   - Evidence: old `os.environ.get("USERNAME", None)`, `"PASSWORD"`, `"CLIENT_ID"`, `"CLIENT_SECRET"`, `"VERIFY"`.
   - Why it matters: `USERNAME` is set by default on Windows, so the old server could pick up the OS login name, and generic `PASSWORD`/`CLIENT_SECRET` vars from other tools could be sent to the ServiceNow instance. The `SERVICENOW_` prefix narrows this. The change reduces accidental credential use.
   - Confidence: medium.

3. **TLS verification can be disabled through config, with warnings suppressed**
   - Evidence: servicenow_api.py:59-60 `if self.verify is False: urllib3.disable_warnings(...)`; README example sets `"SERVICENOW_VERIFY": "False"`.
   - Why it matters: credentials (OAuth body with password and client secret) may be sent without certificate validation if users copy the README example. This is pre-existing behaviour, but the README example now defaults to "False".
   - Confidence: medium.

4. **Errors print the OAuth response to stdout**
   - Evidence: servicenow_api.py:82-84 `print(f"Error Authenticating with OAuth: \n\n{e}\n\nResponse: {response}")`.
   - Why it matters: in stdio MCP transport, stdout is the protocol channel. Error responses could reach the client or logs. This is pre-existing.
   - Confidence: low.
