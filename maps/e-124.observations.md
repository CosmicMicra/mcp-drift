# e-124 — observations (read after labelling)

1. **New always-on audit log written to the current directory by default**
   - Evidence: audit.py `DEFAULT_PATH = "./audit.jsonl"` with default sink "file". Every tool is wrapped with `@audited` (modules/_audit.py).
   - Why it matters: the log contains full tool arguments and results (network configs, client lists, MACs, firewall rules) in a file whose location depends on the process cwd (for stdio clients, often the user's home or the client's directory). This is a disclosure risk if the cwd is shared or synced. The intent (forensics/replay) is security-positive.
   - Confidence: high.

2. **Secret scrubbing is key-name based and may miss UniFi-specific secret fields**
   - Evidence: `SENSITIVE_KEY_PATTERNS = {"passphrase", "x_passphrase", "api_key", "password", "secret", "token"}`, applied to args and results.
   - Why it matters: UniFi objects use fields such as `x_passphrase` (covered) but possibly others (e.g. RADIUS `x_secret` is covered by "secret"; PSK fields with other names might not be). Partial risk of secrets landing in the log.
   - Confidence: low-medium.

3. **The `stdout` sink would corrupt the stdio MCP channel**
   - Evidence: `StdoutSink` writes JSON lines to `sys.stdout`.
   - Why it matters: this is a functional issue in stdio mode if selected. It is not a security issue.
   - Confidence: medium.
