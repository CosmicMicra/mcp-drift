## 1. Server in brief
WebClaw is described as a "WebMCP-native" browser agent. An MCP server (Node.js, `packages/mcp-server`, npm `webclaw-mcp`) and a Chrome MV3 extension (`packages/extension`) let AI assistants like Claude Desktop drive web pages. It either invokes tools that websites declare through the W3C `navigator.modelContext` API (Chrome 146+), or falls back to tools synthesised from DOM forms, buttons, and inputs, with accessibility-tree snapshots. Because it runs inside the user's real Chrome, the README notes it "has access to the user's logged-in sessions, cookies, and installed extensions, and is resistant to bot detection". The extension has `host_permissions: ["<all_urls>"]`.

## 2. The tool(s)
Whole-server item. 8 tools in `packages/mcp-server/src/server.ts` (navigate_to, page snapshot, click, type text, select option, list WebMCP tools, invoke WebMCP tool, screenshot). Tool names, descriptions, and schemas are unchanged; each handler's transport call changed from `nativeClient.request(...)` to `wsClient.request(...)`.

## 4. What changed
- Transport between MCP server and extension: Chrome Native Messaging (stdio) → localhost WebSocket.
```diff
-  const server = createWebClawServer();
+  const port = Number(process.env[WEBSOCKET_PORT_ENV]) || WEBSOCKET_DEFAULT_PORT;
+  const wsClient = new WebSocketClient(port);
+  const server = createWebClawServer({ wsClient });
```
```diff
-      const response = await nativeClient.request('navigate', { url, tabId });
+      const response = await wsClient.request('navigate', { url, tabId });
```
- New `packages/mcp-server/src/ws-client.ts` (+117), new `packages/extension/src/background/ws-bridge.ts` (+134).
- `packages/shared/src/constants.ts`: `+ WEBSOCKET_DEFAULT_PORT = 18080`, `+ WEBSOCKET_PORT_ENV = 'WEBCLAW_PORT'`.
- New dependency `ws ^8.18.0`.
- Installer no longer writes native-messaging host files. It only prints the Claude Desktop config.

## 5. Is `network` reachable?
**Yes.** At server start: `cli.ts` → `new WebSocketClient(port)` → `new WebSocketServer({ port, host: '127.0.0.1' })` (ws-client.ts:23), which listens on loopback. Every tool → `wsClient.request()` → `this.connection.send(JSON.stringify(request))` (ws-client.ts:92). The old version had no socket. It used Chrome native messaging over the process's stdin/stdout.

## 7. Conditions
- Listen: always on start (non-`install`, non-`--help` invocation).
- Requests: only if a WebSocket client is connected (`'Chrome extension is not connected'` error otherwise).
- Connection acceptance: any client that connects to 127.0.0.1:<port>. There is no origin, token, or handshake check in ws-client.ts. The newest connection replaces the previous one.

## 8. Unknowns
