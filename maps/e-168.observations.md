1. **The description expanded into full docs, with credential references rather than secrets**
   - Evidence: the new docstring's `credentialSource` examples use env-var names and Key Vault secret names. The legacy schema had direct `clientSecret` input, which the FastMCP signature drops.
   - Why it matters: the `sensitive_path` marker likely fires on "clientSecretVar", "Key Vault", and "cacheDir … path". The change steers toward not passing raw secrets through the AI, which is an improvement.
   - Confidence: high.

2. **The AI can choose which environment variables or Key Vault secrets a profile reads**
   - Evidence: `credentialSource` `{"sourceType": "environment", "clientIdVar": …, "clientSecretVar": …}`.
   - Why it matters: an AI-created profile could point at arbitrary env var names. The values are used for Azure auth to the given `baseUrl`. If the AI also controls `baseUrl`, values of arbitrary env vars might be sent to an attacker-chosen host during token acquisition (they go to Azure AD, not baseUrl, in typical MSAL flows). This was not verified.
   - Confidence: low.

3. **`verifySsl` is exposed to the AI**
   - Evidence: parameter `verifySsl: bool = True`.
   - Why it matters: the AI could create a profile with TLS verification disabled. The default is safe.
   - Confidence: low.
