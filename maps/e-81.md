## 1. Server in brief
pmx-canvas (`Readme.md`) is "a shared thinking surface for humans and coding agents": an infinite 2D canvas in the browser where files, plans, charts, web pages, and diagrams are placed as nodes and edges, and pinned nodes are exposed to the agent as context. It is driven from a CLI, an MCP server (`src/mcp/server.ts`, started with `bunx pmx-canvas --mcp`), an HTTP API, or a Bun TypeScript SDK. Users are developers using coding agents (Claude Code, Codex, Cursor, …). The MCP server either starts a local canvas HTTP server (default port 4313) and opens the browser, or (new in this version) connects to an already-running canvas daemon over HTTP.

## 5. Is `network` reachable from this tool?
**Yes.** The named helper is the one actually called:
`canvas_redo` (server.ts:948) → `ensureCanvas()` (server.ts:950→79) → `startResourceNotifications(canvas)` (server.ts:85) → `void watchRemoteCanvasEvents(c.remoteBaseUrl)` (server.ts:151) → `fetch(\`${baseUrl}/api/workbench/events\`)` (server.ts:121).
Also independent of that helper: `createCanvasAccess`/`refreshCanvasAccess` → `readHealth` → `fetch(\`${baseUrl}/health\`)` (canvas-access.ts:633) on every call, and `RemoteCanvasAccess.redo/getHistory` → `fetch` (canvas-access.ts:324).
`watchRemoteCanvasEvents` is reached only when `resourceNotificationServer` is set (it is, in `startMcpServer`, server.ts:212) and the access is remote.

## 7. Conditions
- `/health` probes: always, on every tool call (first call via `createCanvasAccess`; later calls via `refreshCanvasAccess` only while still local).
- Remote mode: a candidate URL returns `/health` with `ok === true` and either no `workspace` or a `workspace` equal to the canonicalised cwd.
- SSE watcher: remote mode and `resourceNotificationServer` set; started once per distinct base URL; loops forever.
- Local mode (no daemon found): starts the local canvas server and opens the browser (as before).
