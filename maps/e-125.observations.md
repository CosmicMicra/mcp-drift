# e-125 — observations (read after labelling)

1. **New: an agent can execute arbitrary Python in the user's live session**
   - Evidence: clauder-py/server.py `exec(compile(code, "<clauder>", "exec"), STATE.namespace)`.
   - Why it matters: this is the stated purpose ("The agent then executes code in this session … Every line it runs is logged and attributed"). It is opt-in (the user calls `clauder.start()`). It extends the existing R-execution capability to Python.
   - Confidence: high.

2. **Localhost code-execution endpoint without a token by default**
   - Evidence: `start(..., require_token: bool = False, ...)`. The token check runs only `if STATE.require_token` (server.py:268). It binds to `127.0.0.1`.
   - Why it matters: any local process (and possibly browser pages, if the handler accepts simple cross-origin POSTs; not verified) can execute code in the user's Python session while it runs. A token is generated and written to the discovery record but not required by default.
   - Confidence: medium-high.

3. **Positive: session binding now fails closed**
   - Evidence: clauder-mcp/server.py:137-155 refuses to reroute code when the bound session is lost, changed (PID identity), or ambiguous.
   - Why it matters: this prevents code intended for one session from running in another.
   - Confidence: high.
