## 1. Server in brief
blender-ai-mcp is a Python (FastMCP) MCP server with a companion Blender add-on. The server exposes validated, structured Blender operations (scene, mesh, modeling, materials, UV, armature, extraction, …) to an AI. The add-on executes them in Blender over JSON-RPC on TCP sockets (`BLENDER_RPC_HOST`). The README motivates it as safer and more reliable than letting the AI write raw `bpy` scripts. Users are 3D artists and developers driving Blender with AI assistants. In this range a "Router Supervisor" was added: it intercepts tool calls and may correct or expand them using intent classification (LaBSE sentence embeddings, a LanceDB vector store, workflow matching).

## 5. Is `env_secrets` reachable from this tool?
**Yes, as reads of non-secret configuration env vars.** Chain: `uv_list_maps` (uv.py:9) → `route_tool_call` (router_helper.py:46 `is_router_enabled()` → `config.ROUTER_ENABLED` from `os.getenv("ROUTER_ENABLED")`) → `get_router()` (di.py:225) → `get_intent_classifier()` / `get_workflow_classifier()` → `get_labse_model()` (di.py:138) → `os.getenv("PYTEST_CURRENT_TEST")`, `os.getenv("HF_HUB_OFFLINE")`. The named helper `get_labse_model` is the one called, on the first tool call that builds the router singleton. The same call also makes a network model download possible.

## 7. Conditions
- Router path: `ROUTER_ENABLED` true (default) and `get_router()` returns an instance.
- Model load/env reads: first construction of the classifiers (singleton). Network download only if the model is not cached and `HF_HUB_OFFLINE` is not set. Failure falls back (returns None) with a warning.
- On router failure, `route_tool_call` falls back to direct execution (per its structure; details at router_helper.py:53+ not fully read).
