## 1. Server in brief
MCP Atlassian Server (by phuc-nt) connects AI agents (primarily Cline, also Claude Desktop and Cursor) to Atlassian Jira and Confluence Cloud. It provides read-only "resources" and action "tools" (create/update issues, sprints, filters, dashboards, Confluence pages and comments, …). It authenticates with basic auth (user email + API token) against `https://<site>.atlassian.net`, configured via the env vars `ATLASSIAN_SITE_NAME`, `ATLASSIAN_USER_EMAIL`, `ATLASSIAN_API_TOKEN`. In this range the 1710-line `src/utils/atlassian-api.ts` was split into resource/tool API modules.

## 5. Is `env_secrets` reachable from this tool?
**Yes.** `createFilter` handler (create-filter.ts:59) → `process.env.JIRA_EMAIL || process.env.ATLASSIAN_EMAIL || process.env.ATLASSIAN_USER_EMAIL` (create-filter.ts:68-71) when `context.atlassianConfig.email` is empty. These are email addresses. They are logged to stderr. The API token reaches stderr through `JSON.stringify(context)` in the error branches (context contains `atlassianConfig.apiToken`). None of this is returned to the AI (the error responses contain only fixed strings).

## 7. Conditions
- Env fallback: `context.atlassianConfig.email` is falsy. Since index.ts exits at start if `ATLASSIAN_USER_EMAIL` is missing and copies it into `atlassianConfig.email`, this branch should not occur in normal runs.
- Context dump branches: missing `atlassianConfig` (not expected given the wrapper) or no email anywhere.
