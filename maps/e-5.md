## 1. Server in brief
Context Mode is an MCP server (npm `context-mode`, also a Claude Code plugin) that addresses context-window bloat in coding agents. Its "sandbox" tools run commands or fetch data and return only compact summaries (the README claims "315 KB becomes 5.4 KB"). It also gives "session continuity": file edits, git operations, tasks, errors, and decisions are tracked in SQLite with FTS5 and re-injected selectively after compaction. It targets Claude Code, Codex, OpenCode, Cursor, and similar agents, and installs hooks and routing instructions per platform. `ctx_upgrade` is a meta-tool for upgrading the plugin itself.

## 4. What changed for this tool
Old handler body:
```ts
-    const pluginRoot = dirname(dirname(fileURLToPath(import.meta.url)));
-    const cmd = `node "${pluginRoot}/build/cli.js" upgrade`;
```
New handler: pluginRoot detection, `cli.bundle.mjs` preference, and an inline fallback that **writes a script file** and returns `node "<pluginRoot>/.ctx-upgrade-inline.mjs"`. The generated script clones the GitHub repo, runs `npm install` and `npm run build` in the clone, copies build outputs over the plugin directory, and runs `npm install --production`.
The description and the returned instruction text ("Run this command using your shell execution tool", checklist format) are unchanged.
The "return a shell command for the AI to run" behaviour **already existed**. New: the server itself writes an executable `.mjs` file in some installations, and the command it returns can include clone/build/install steps.

## 5. Is `shell` reachable from this tool?
**Not inside the server process.** The handler does not call `exec`/`spawn`. It returns a command string, and the description says the AI "MUST run the returned command using your shell tool". The `execFileSync` calls appear only as text inside `scriptLines`. They execute only if the AI client runs `node .ctx-upgrade-inline.mjs`. The server process itself writes that file (`writeTmp(tmpScript, scriptLines)`) when neither CLI file exists. In the other two branches, the returned command runs the existing CLI `upgrade` (src/cli.ts:416), which is unchanged in its role.
