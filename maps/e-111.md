## 1. Server in brief
mcp-windbg is a Python MCP server for Windows that drives the Microsoft debuggers `cdb.exe` (user-mode crash dumps and `-remote` debug servers) and `kd.exe` (kernel targets over KDNET, named pipe, or serial). An LLM can open a dump or attach to a target, run arbitrary debugger commands (`kb`, `!analyze -v`, `!process 0 0`, …), and reason about the output. It targets developers and support engineers doing crash-dump triage and live or kernel debugging. It connects to local debugger executables, symbol paths/servers, and (for remote/kernel sessions) the debug transports the user supplies.

## 5. Is `fs_write` reachable?
**Yes**, but only conditionally. Chain: `open_cdb_dump` (server.py:537) → `CDBSession()` → `DebuggerSession.__init__` → `_enable_unicode_log()` → `tempfile.mkstemp(...)` (creates an empty temp file) → `os.remove(path)` → `.logopen /u {path}` (the cdb.exe subprocess writes the log). Same via `open_kd_session` → `KDSession` (class default `_engine_is_local = True`). Not reached via `open_cdb_remote` (`_engine_is_local = False`). Not reached at all when `_acp_is_multibyte()` is False (single-byte code page or non-Windows).

## 7. Conditions
- Temp-file create/delete and `.logopen`: Windows host with a multibyte ANSI code page (932/936/949/950/65001), `_engine_is_local` True (dump or kd session), and the debugger started successfully.
- Log read: `_log_active` True (log file existed after `.logopen`).
- Log delete: on `shutdown()` whenever `_log_path` is set.
- Any exception in `_enable_unicode_log` → `_cleanup_log()` and pipe path.

## 8. Unknowns
- Temp directory location depends on the runtime `TMP`/`TEMP` (not static).
- Exact debugger behaviour of `.logopen /u` (external binary).
