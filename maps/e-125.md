## 1. Server in brief
ClaudeR ("The Modern Researcher's Toolkit") connects RStudio to Claude Code, Codex, Gemini CLI, or any MCP-based agent for interactive coding, multi-agent orchestration, and automated manuscript auditing. An R package/RStudio add-in runs a local HTTP endpoint in the user's live R session. The MCP server (`clauder-mcp`, Python; also `inst/scripts/persistent_r_mcp.py`) discovers sessions and sends code to execute there (`execute_r`, `execute_r_with_plot`, …), returning output and plots. In this range a **Python counterpart, `clauder-py`**, was added. It exposes a live Python session (Positron, Jupyter, VS Code, REPL) the same way, and the MCP server learned to route to Python sessions.

## 2. The tool(s)
Whole-server item. `clauder-mcp/src/clauder_mcp/server.py` (+461/−…) changed: session discovery and binding (`get_r_addin_url`, `_session_info`, `_session_language`), with language-aware routing (`R_ONLY_TOOLS` refused for Python sessions, labels "Python"/"R"). The execute tools send code to whichever session is bound.

`clauder-mcp` itself does not call `exec`. The dynamic-code sink is in the new `clauder-py` package, which runs inside the user's Python process and is reached via the MCP execute tools when a Python session is registered.

## 4. What changed
- New package `clauder-py` (`__init__.py`, `discovery.py` +166, `server.py` +420, tests). It executes received Python code with `exec(compile(code, "<clauder>", "exec"), STATE.namespace)`.
- `clauder-mcp/server.py`: session discovery and binding hardening (PID identity, "BOUND_SESSION_LOST_OR_AMBIGUOUS", "MULTIPLE_SESSIONS" errors), Python-session support.
- R side: `R/ui.R`, `R/coordination.R` changes. CITATION files and a discovery-reliability CI workflow were added.

## 5. Is `dynamic_code` reachable?
**Yes, by design, now also for Python.** MCP execute tool → bound session URL (`get_r_addin_url`) → POST to the clauder-py localhost server → `exec(compile(code, …))` in the user's session namespace. Executing AI-written R code in the user's R session existed before. Python execution is the new part.
