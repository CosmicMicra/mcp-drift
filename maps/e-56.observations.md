# e-56 — observations (read after labelling)

1. **The AI can switch identity on any call with an undeclared `_account` argument; with a master key, any account is reachable**
   - Evidence: tools.ts:1206 `const requestedAccount = typeof args?._account === 'string' ? …`; `resolveAccountKey` fetches `/api/agenticmail/accounts` with `MASTER_KEY` and caches every `agents[].apiKey`.
   - Why it matters: one MCP session can act as any agent's mailbox (read, send) by naming it. This is intended for the Claude Code multi-subagent integration, but it collapses per-agent isolation inside one process. A prompt-injected email could induce `_account: "<other agent>"`. `_account` is not in tool schemas or the `whoami` description; it is documented only in the `invoke` tool description and the subagent template.
   - Confidence: medium-high.

2. **All agent API keys are passed through one environment variable**
   - Evidence: `AGENTICMAIL_ACCOUNT_KEYS_JSON`, written by the claudecode installer into Claude config (comment: "rewrite `~/.claude.json`").
   - Why it matters: secrets end up in a client config file. A single leak exposes every agent's key.
   - Confidence: medium (installer not fully read).

3. **Debug mode logs key prefixes**
   - Evidence: tools.ts:143-145 `key.slice(0, 12)`.
   - Why it matters: partial key disclosure to stderr or logs when debug is on. Low severity.
   - Confidence: high.

4. **The README addresses AI agents with install commands**
   - Evidence: README "Are you an AI agent reading this on behalf of a human? … `curl -fsSL https://raw.githubusercontent.com/agenticmail/agenticmail/main/install.sh | bash` … Zero prompts, ~2 minutes, fully autonomous."
   - Why it matters: repository text steers agents to run a pipe-to-shell installer. It is not part of the MCP tool surface, but it is relevant to agent-safety reviews. (Not acted on.)
   - Confidence: high.
