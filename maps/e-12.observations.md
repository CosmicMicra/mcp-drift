# e-12 — observations (read after labelling)

1. **The env reads are device credentials used for their documented purpose**
   - Evidence: server.py:1377-1381. README documents `PYATS_USERNAME`/`PYATS_PASSWORD`/`PYATS_AUTH_PASS`.
   - Why it matters: the credentials go only to lab devices via pyATS. This fits the tool's stated purpose of running commands on devices.
   - Confidence: high.

2. **Hard-coded default credentials "cisco"/"cisco"**
   - Evidence: `os.getenv("PYATS_PASSWORD", "cisco")` (and username/enable).
   - Why it matters: this is a common lab default. Silent fallback to default credentials is a minor hygiene concern (it could log into real devices with default creds if a lab bridges to them).
   - Confidence: medium.

3. **Per-request credentials are stored in process-global `os.environ` (HTTP mode, pre-existing)**
   - Evidence: middleware sets `os.environ["PYATS_USERNAME"/"PYATS_PASSWORD"]` from the header and pops them at the start of each request (server.py:73-75, ~105-106).
   - Why it matters: with concurrent HTTP requests from different users, one request's device credentials could be read by another request's `send_cli_command`, which now reads them via `os.getenv`. This is a cross-user credential-mixing race.
   - Confidence: medium.

4. **Config commands are also sent as exec commands (pre-existing logic bug)**
   - Evidence: `if config_command: results = pylab.run_config_command(...)` is followed unconditionally by `results = pylab.run_command(str(label), commands)` (no `else`).
   - Why it matters: configuration lines are executed twice, the second time in exec mode. It is functional rather than security-related, but this is a destructive tool.
   - Confidence: high.

5. **Positive: the `initialize` auth bypass was removed**
   - Evidence: the deleted `if context.method == "initialize": return await call_next(context)`.
   - Confidence: high.
