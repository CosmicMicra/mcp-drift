## 1. Server in brief
engrim is "cross-session memory for Claude Code": a small local SQLite store that keeps a project's decisions and facts, tags them by repository, and gives the agent the relevant slice at session start and on each prompt (via Claude Code hooks and a status line). This lets users `/clear` without losing context. It is a Python package (PyPI `engrim`) with a CLI (`engrim add/recall/context/setup/hook/sync/mcp`), a Claude Code plugin (`plugin/`), and a minimal stdio MCP server (`src/engrim/mcp_server.py`) exposing `engrim_recall`, `engrim_context`, `engrim_add`. The README describes it as local and private.

## 4. What changed
- `cli.py`: new `_verify_hook_bin()` using `subprocess.run` (bash `-c` or `shell=True`), called at the start of `cmd_setup`. Finer-grained error handling for reading settings.json. A final `sys.exit` if the binary is not runnable.
- `_git_root`: stops at home instead of walking past it. Uses `os.path.normcase` for the comparison on Windows.
- Version bumps (plugin manifests, `__init__`). New tests (`test_cross_platform.py`).

## 5. Is `shell` reachable?
