## 1. Server in brief
mcp-unifi is a Python (FastMCP) MCP server for self-hosted UniFi gateway management (UCG-Fiber, UDM, …). Its ~41 tools cover devices, networks/VLANs, WiFi SSIDs (full CRUD), firewall rules (full CRUD), switch port profiles, port forwards, DHCP, clients (block/unblock), observability, and composite workflows with rollback. It runs over stdio (Claude Desktop, `uvx mcp-unifi`) or Streamable HTTP (container on port 3714). Every tool returns JSON. In this range the monolithic `server.py` was split into `modules/network/*`, a multi-controller config (`controllers_file` YAML) and a dispatcher were added, and **every tool call is now written to an audit log**.

## 2. The tool(s)
Whole-server item. All tools moved from `src/mcp_unifi/server.py` (old, ~1795 lines removed) into `src/mcp_unifi/modules/network/*.py` and are wrapped with `@audited("<tool_name>")` (modules/_audit.py). Whether tool names and descriptions are unchanged was not diffed per tool (see Unknowns).

## 4. What changed
- New `src/mcp_unifi/audit.py` (AuditEvent, scrub, FileSink/StdoutSink/SyslogSink, env-built singleton) and `modules/_audit.py` (`audited` decorator).
- New `dispatcher.py` (+170), `config.py` (+198: multi-controller, YAML file), and `modules/network/*` (tool implementations).
- `server.py` reduced to wiring. The old server had no audit file writes (old `server.py` grep showed only an "audit log" mention in a docstring and the read-only `audit_open_ports` tool).

## 5. Is `fs_write` reachable?
**Yes.** Every audited tool → `audited` wrapper → `AuditLog.emit` → `FileSink.write` → `open(path, "a")` (audit.py:164) with the default sink "file" and path `./audit.jsonl`, unless `MCP_UNIFI_AUDIT_SINK` selects stdout or syslog. The path is operator-configured or the default, not AI-controlled. Content includes AI-supplied args and controller results after key-based scrubbing.
